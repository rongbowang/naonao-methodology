# 画面规则（细则）

## 一、每镜必须写满的 19 项 + 4 个量化栏位

时段与句数 · 景别 · 机位 · 焦点 · 构图 · 四层画面构成（背景/中景/人物/氛围）· 光影 ·
色彩 · 元素表（名称/坐标/尺寸/颜色/动画）· 角色表演 · **逐句动作表（精确到像素）** ·
运镜 · 转场 · 音效 · 字卡规格 · 连续性 · 出入画方向 · 颜色清单 · 状态

**四个必填数字栏**（不填就是没写完）：
1. **包围盒核算表** —— 每个元素 top/bottom/left/right，逐行核 `bottom ≤ 760`
2. **最小可见尺寸** —— 线宽 ≥ 10px、字号 ≥ 40px（1920 宽）、缝类间隙 ≥ 24px
3. **常驻微动** —— 除了句子动作，什么在持续动、周期多少（防死段）
4. **素材锚点语义** —— 调每个 prop 时，(x,y) 到底是哪个点

## 三、换画幅的四条硬规矩（2026-11-03）

1. **纵向不动**（高度不变时，地平线/球心/桌沿是节奏不是比例）
2. **横向靠"变大"补，不靠"留白"补**：多出来的宽度交给主体放大 1.1~1.25 + 往画心挪
3. **放大必然下压**：半径 +10 → 球底 +10，圆心同步上移
4. **居中要重新验**：`|主体中心 − K.CX| > 60px` 就重排。**预检脚本查不出这条，只有抽帧能看出来**

## 三·五、相机与分组的两条（2026-11-04，NO.21 返修）

### 1. 相机平移必须 ≤ 缩放余量

`#stage` 是 `overflow:hidden`，svg 的 viewBox 只有画布那么大 —— **viewBox 外没有像素**，
出血 rect 也救不了（同样被裁掉）。

```
|t.x| ≤ (s − 1) · VW / 2      |t.y| ≤ (s − 1) · VH / 2
```

`web/js/lib.js` 的 `camClamp(s, x, y)` 已经钳住了，但**别一开始就写超**：
`{s:1.15, x:419}` 这种"推近主角特写"会被钳成 x=144，构图和你想的不一样。
要挪人，调主体坐标；要特写，居中推。

### 2. 分组必须是真分组

建了 `const G1 = K.sp(svg,"g",{})` 之后，**这一组的每一个元素都要用 `G1` 当 parent**。
写成 `PS.dragon(svg, {...})` 就是漏了 —— `G1` 的 opacity 对它无效，切景时它会一直留在画面上，
在某个交叉淡出的瞬间透出来（NO.21 的"1分40秒闪到恶龙"就是这么来的）。

```powershell
# 自查：这个组里有几个元素
(Select-String -Path js\scenes.js -Pattern '\(G1,' -AllMatches).Matches.Count
# 再看有没有漏网的（该进组却写在 svg 上）
Select-String -Path js\scenes.js -Pattern '\(svg,'
```

## 五、几条"看不出但致命"的

- `K.txt()` 是 HTML div，塞进 `<svg>` 不显示且不报错
- 字幕安全区：文字底边 ≤ 760（16:9）；开 camera 后按 scale 折算
- 小动作不算动，**面积才算**：扫光 / 数字滚动 / 粗线呼吸 / 整块变暗，5px 波纹量不出来
- 改过 `scenes.js` 再渲染，**必须先把 `web/_seg/` 挪走**，否则断点续跑用旧段合出旧画面且"成功"
- `capture.mjs` 的 worker **端口可配**（`--port`，父进程默认 8131、`--par` 默认 6）。
  `render_all.py` 也从 `--port` 起按槽位分配，`--par=N` 并发。
  **多期并行仍然要错开端口段**：一期 `--port=8140`、另一期 `--port=8150`，
  不要两期共用同一段（那才是 EADDRINUSE 的真正原因，不是"8130 被占死"）。
- `_shot.mjs` 走 `file://` 打开 `index.html`，**不启服务、不占端口**，几期可以同时截。
