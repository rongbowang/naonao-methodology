# 作画开发交接（`06_画面绘制.md` → `web/js/scenes.js`）

> 给"只负责画场景"的开发 agent 看的。它不碰文案、不碰 timeline、不碰渲染参数。
> 一次性把边界、并行排法、验收命令讲清楚，开发就不用来回问。

## 一、边界：只准动一个文件

**唯一可写文件**：`30 制作/<期目录>/web/js/scenes.js`

其余全部**只读**（读了用来对照，不许改）：

| 文件 | 用它干什么 |
|---|---|
| `06_画面绘制.md` | 唯一施工图。逐句动作表里每句的「动作 / 级 / 精确量」就是这一句要画的 |
| `web/timeline.json` | 台词与逐字时间。`shots[i].lines[j]` 的 `g0/g1`、`chars[].t0/t1` 是动画锚点 |
| `script.py` | 台词原文，和 timeline 应一致；不一致以 timeline 为准并报回来 |
| `web/js/lib.js` | 导演工具库：`W/LB/LP/cam/gpop/popIn/fade/chip/bigNum/bar/glow/outroStd` |
| `web/js/kit.js` | `K.SAFE_BOT`（横屏 = **760**）、`K.VW/VH`、`K.div/K.el/K.seg` 等 |
| `web/index.html` | 图层与字幕框结构，只读不写 |

**不许改**：`lib.js` / `kit.js` / `engine.js` / `index.html` / `capture.mjs` / `_shot.mjs` / `timeline.json` / `script.py` / `06_*.md`。

**也不许碰素材库**：`20 素材_只读/`（含 `graphics/` `sfx/` 与三个 catalog）与 `web/js/props*.js`。素材在开工前就该就位，不是作画阶段现做的。

> 缺一个工具函数怎么办？**在 `scenes.js` 内部写局部函数**（文件顶部、`"use strict"` 之后）。
> 千万别就地改 `lib.js` —— 每期目录里各有一份 `lib.js` 副本，改一份等于又造一个分叉版本，下期抄走就传下去了。

## 一·五、开工前提：素材已就位（2026-11-07 新增）

作画之前，`06_画面绘制.md` 的 `## 素材盘点` 表 B 必须**全是 `✅ 已入库`**。这一步由流程方在作画之前单独完成，**不是作画 agent 的活**。

| 情况 | 你做什么 |
|---|---|
| 表 B 全 ✅ | 直接开工 |
| 表 B 有不是 ✅ 的行（空白 / 待补 / ⚠️ 描述不足） | **停下报回来**，不要自己临时画一个凑上 |
| 作画途中发现还缺素材 | 同样停下报回来，写清缺什么、用在哪镜哪句 |

为什么卡这么死：素材现画的时候，没时间调比例、没时间对锚点、没时间验包围盒，成片里就是歪的、切边的、被字幕压的。素材先入库还能反复改；画面渲完再改，要重渲整片（130 分钟起）。

## 二、并行：能并行，但要守三条

六期（11-09 / 11-10 / 11-11 / 11-12 / 11-14 / 11-15）同时开六个开发会话 **改代码不会冲突**：
每期的 `scenes.js` 在各自目录，`_pilot` 产物也各在各家。

冲突只出在两处：

| 冲突点 | 为什么 | 规矩 |
|---|---|---|
| **渲染端口** | 撞端口时 `capture.mjs` 的 `EADDRINUSE` 不会让进程失败，还会合出一个能播的空 mp4、`exit 0` —— 静默失败 | **2026-11-07 已改为机制保证**：`render_all.py` 内置全局渲染锁（原子创建 + 心跳），同一台机器同时只有一个渲染在跑，其余自动排队并打印「另一路渲染正在跑…排队」。**不用再手工分配端口段**，`--port=` 只在真要错开时才用 |
| **CPU / 机器卡顿** | `--par=4` 一期就 4 个 chrome worker，六期同时渲 = 24 个，机器卡到看不出是谁的问题 | 同时**最多 2 期在渲**，`--par` 压到 2；其余期排队，或先只做代码 + 单帧截图验收 |

> 锁的实测结论（2026-11-07）：8 / 20 / 40 个进程同一时刻抢锁，全部只有一个在跑、零重叠、零卡死；持锁进程被强杀后，下一路最多等 60 秒自动接管。
> **但要记住锁的边界**：它只管 `render_all.py`。**绕过它直接 `node capture.mjs`，锁等于不存在** —— 这也正是「两路并发、一路静默无产物」的成因。
>
> 端口自检：开渲前 `render_all` 会先探 `--port` 起 `--par` 个端口；被占就报错退出（exit 4），不会闷头跑出一个空片。被占多半是上次渲染被强杀后留下的孤儿 node。

`02 工具` 里的脚本是所有期共用的只读工具，多期同时调不会打架（`render_all.py` 内部有日志锁）。

- 崩 `Cannot read properties of undefined (reading 'build')` = `Scenes[shot.scene]` 没定义，**不是元素写错**，是整镜没画。

- 静帧里文字底边超过 760 px 就是压字幕，必须挪。

## 四、交付标准

1. `define("open"|"do"|"solve"|"end"|"outro", ...)` 五个键**全在**，键名与 `timeline.json` 的 `shot.scene` 逐字相同。
2. `outro` 那行**保留原样**（`outroStd({ no: "NO.xx" })`），只核对期号对不对，别重写。
3. 每句台词都有对应动画：`g0→g1` 之间画面不能是死的。
4. 全部元素底边 ≤ 760；开 camera 放大时按 scale 折算后仍 ≤ 990。
5. `preflight.py NO.xx` 的「Scenes 覆盖」= PASS。
6. 单镜 `--pilot` 渲完能播出、且**不改动** `render.mp4`。
7. 没有自己造素材：`scenes.js` 里用到的每个画材/音效都能在 `props*.js` 或 `sfx_catalog.json` 里查到；缺的已经报回来，不是自己临时补的。
8. `preflight.py NO.xx` 的「素材盘点」= PASS（表 B 全 ✅，引用全部查得到）。
