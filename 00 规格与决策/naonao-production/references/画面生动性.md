# 画面生动性（2026-11-04 建立，用户退改 NO.21 后总结）

> 用户原话：「我希望的是**每一句话最好都能够有对应的动画**。」
> 这一页解决的就是这件事：为什么有些画面"该有的都画了"却还是死，以及怎么改。

---

## 一、总纲：一句话

**台词的动词，必须在画面上真的发生一次。**

不是"画面里出现了台词提到的东西"，是"这件事在观众眼前做完了"。

| 台词 | ✗ 不合格 | ✓ 合格 |
|---|---|---|
| 来解救被恶龙掳走的公主 | 画一个王子站着 | 公主在场 → 恶龙入画 → 拎起她 → 拖出画 |
| 选对公主和王位都归你，选错帮恶龙带孩子 | 两扇门闪一下金光 | 左卡（公主+王冠）／右卡（婴儿+奶瓶）依次滑入 |
| 恶龙亲手推开了那扇门 | 门自己变亮，龙站旁边 | 龙贴到门边 + 门口碎石溅起 + 门扇消失 + 暖光涌出 |
| 从此走向了人生巅峰 | 王座厅全景站着三个人 | 国王起身 → 摘下自己的王冠 → 飞到王子头上 → 公主怀里多一个孩子 |

**判据（写完一场戏，逐句问）**：
把这一句台词念一遍，闭眼想画面 —— **能不能说出"这一秒画面里什么东西在动、往哪动"**？
说不出，就是没画。

## 二、动作分级（D 级不算动）

同一句台词，四种画法，只有 A/B 能过：

| 级 | 做法 | 例 | 判定 |
|---|---|---|---|
| **A 叙事动作** | 角色/物件完成一个有起因有结果的动作 | 龙把公主拖出画、国王把冠飞给王子 | 最好，优先 |
| **B 状态迁移** | 物件从一个可命名的状态变成另一个 | 门关→门开、表格四格→塌成一句 | 合格 |
| **C 强调** | 已有的东西脉冲/闪烁/放大 | 门闪金光、表格脉动 | 只能当**底噪**，不能当这一句的答案 |
| **D 装饰** | 常量微动、扫光、呼吸 | stage2 自带的三道扫光 | 只用来防死段，与叙事无关 |

**C 级滥用是本期最大的病**：句 5「选对…选错…」整整 6 秒，只让两扇门闪了一下金光。
机器体检全绿（有变化、帧差够），观众看到的是"画面卡住了"。

**规矩：每句台词至少要有一个 A 或 B。C 可以叠在上面，但不能顶替。**

## 三、七条硬规矩

### 1. 一句一动作，动作要能被命名

写完一场戏，列一张表：`句号 | 台词 | 这一句的动作是什么`。
某一行的"动作"栏写不出**动词**（写成"门亮了一下""卡片出现"这种），回去重画。

### 2. 一句话塞了三件事，就拆句

**这是最重要的一条。** 一个画面演不了三件事，硬演的结果是三件都没演。

```
✗ 门后台阶尽头站着公主，你带着公主回到老国王身边，从此走向了人生巅峰。
  → 实际画面：台阶尽头坐着老国王，公主站在台阶中段，王子根本没画
  → 用户："1分27秒说门的尽头站着公主，你他妈现在的尽头站的是老国王"

✓ 门后台阶尽头站着公主。      → 门内台阶景，公主站最顶上一级（这一格不许出现国王）
✓ 你带着公主回到老国王身边。  → 王座厅全景，王子与公主并肩（"你"必须在场）
✓ 从此走向了人生巅峰。        → 国王摘冠给王子，公主怀里多了孩子
```

**拆句的代价是重配配音（约 0.3 元），不拆的代价是整段作废。永远选拆。**

### 3. 说谁，画谁

台词点名谁，那个人**必须在这一格里**，并且是能认出来的那个。

- 「你带着公主回到老国王身边」→ 画面上必须有"你"（王子）。上一版只有国王和公主。
- 「门的尽头站着公主」→ 尽头就必须是公主，不能是国王。
- 反派/配角可以小、可以暗，但不能缺席。

### 4. 前后镜不许互相拆台（同一个动作只能发生一次）

```
✗ 02_solve 末句「你听见那声不能，转身就推开了左边那扇门」
  03_end 首句「恶龙亲手推开了那扇门」
  → 同一个门开了两遍。用户："你把前面那一句改成你选择了那扇门"

✓ 前面降级为「选择了那扇门」（走到门前、门缝亮起、地上一圈金光）
  后面保留「恶龙亲手推开」（门扇消失、暖光涌出、碎石飞）
```

**改法不是把后面那句改掉，是把前面那句的动作降级。** 谁是这件事的施动者，只能有一个。

### 5. 每一组的所有子元素，必须加在这个组里

**这是最隐蔽的一条，会让画面凭空闪出前一景的东西。**

```js
// ✗ 错的：G1 只是个空壳，门和龙都挂在 svg 顶层
const G1 = K.sp(svg, "g", {});
const dL = PS.stoneArch(svg, {...});     // ← 加到了 svg
const dr = PS.dragon(svg, {...});        // ← 加到了 svg
// 切景：ctx.G1.setAttribute("opacity", 0)  ← 对 dL/dr 完全无效！
// 后果：句4→句5 交叉淡出时，底下那层从未消失的"洞口+恶龙"透出来
// 用户："两边的话都不可信之后，动画为什么闪到了龙那里（1分40秒）"

// ✓ 对的：
const G1 = K.sp(svg, "g", {});
const dL = PS.stoneArch(G1, {...});
const dr = PS.dragon(G1, {...});
```

**检查方法**：每建一个组 `G1`，`grep -c "(G1," scenes.js` 必须等于这一组的元素个数。
凡是写成 `(svg,` 的，都是漏的。

### 6. 切景要么快，要么硬切，不要叠半秒

两个**全屏不透明底**的组交叉 0.6 秒，观众看到的是"两个画面糊在一起"（本期 G1→G2 实拍就是这样：
门、暖光、台阶、公主同时可见，脏得没法看）。

- 同景内元素进出：0.3~0.6s 交叉，没问题
- **两个全屏景之间**：≤0.3s，或者干脆 0.02s 硬切（更像"换场景"）
- 上一景的最后 0.2 秒不要放重要动作 —— 它一定在淡出里被吃掉

### 7. 相机不许把背景推穿

`#stage` 是 `overflow:hidden`，svg 的 viewBox 只有画布那么大 —— **viewBox 外没有像素可以拉进来**，
出血 rect 也救不了（同样被裁掉）。

```js
// ✗ s:1.15 + x:419 的"推近主角特写" → 画面右移 419px，左边露出 419px 空底
//   用户："背景在左边有空的，背景没铺满"
// ✓ lib.js 已加 camClamp：|平移| ≤ (s−1)·VW/2，超出部分自动钳回去
```

**推论**：想把人摆到画面某个位置，靠**调主体的坐标**，不是硬推相机。
推近只能"就地居中"，或者平移不超过缩放余量。

## 四、素材层面的三条

### 1. 大小关系决定语义

同一个物件，"大"和"小"讲的是两件事：

- 恶龙 `s=0.95`（高 285）配公主 `s=1.9`（高 295）→ 一样高 → 读成"两个人并排站着"
- 恶龙 `s=1.45`（高 435）→ 高出一头多 → 才读成"恶龙把公主拎走了"

**判据**：吃人的 / 抓人的 / 威胁的，视觉高度至少是受害者的 **1.4 倍**。

### 2. 需要"动势"就加逃逸粒子

门被推开、石头落地、角色冲出画面 —— 主体移动之外再给 5~8 个小碎块沿发散方向飞出、边飞边淡出。
成本 6 行代码，效果是"这件事真的发生了"。

```js
const dp = clamp(seg(tl, t0 + 0.10, t0 + 1.05));
dust.forEach((el, i) => {
  const a = 0.10 + i * 0.20;
  el.setAttribute("cx", (1150 + 130 * dp * Math.cos(a)).toFixed(1));
  el.setAttribute("cy", (712 - 60 * dp * Math.sin(a) + 150 * dp * dp).toFixed(1));
  el.setAttribute("opacity", (0.85 * (1 - dp)).toFixed(3));
});
```

### 3. 同一场景换"景别"要换"布景"

- 洞口 → 门内台阶 → 王座厅：三个完全不同的背景（岩体 / 台阶透视图 / 地砖透视 + 王座）
- 不要指望"同一个洞穴背景 + 换几个人"能表达"回到了王宫"。

## 六、"剪开 / 重拼"类动作的六条铁律（NO.22 血泪）

这一类动作最容易被糊弄过去，也最容易被观众戳穿。**画面必须是"证据"，不是"示意"。**

### 1. 几条线，剪刀就要走几次

NO.22 第一版：画了三条切线，剪刀只走了第一条，另外两条"自己断的"。
观众看到的是：一条线被剪开，另两条突然消失。**没有"剪"这个动作。**

判据：数一下台词里的动作数，画面上就要有几次对应的运动。
"顺着格线，两块三角，两块斜的" = 三条线，就是剪刀走三趟，每趟 0.5~0.7 秒。

### 2. ★ 四块的面积必须合计等于原图（最狠的一条）

NO.22 第一版的四块是我随手写的多边形，**面积合计 71，原图只有 64** ——
它们互相重叠 7 平方格。所以"剪开"永远假：四块根本不是从这张纸上剪下来的，
一分开就露馅（重叠部分变成双层纸，缺口变成空洞）。

**动手前先用鞋带公式验一遍：**
```python
def area(pts):
    return abs(sum(pts[i][0]*pts[(i+1)%len(pts)][1] - pts[(i+1)%len(pts)][0]*pts[i][1]
                   for i in range(len(pts))))/2
assert abs(sum(map(area, PIECES)) - 8*8) < 1e-6
```
三个切点把 8×8 切成四块的正确解：
`[[0,0],[5,0],[0,2]]` 5 · `[[5,0],[8,0],[0,3],[0,2]]` 7 ·
`[[0,3],[5,1.125],[5,8],[0,8]]` 29.6875 · `[[5,1.125],[8,0],[8,8],[5,8]]` 22.3125

### 3. 分离：沿各自重心向外推，旋转绕自己重心

- 推开距离 60~110px（太小看不出分开，太大飞出画）
- 每块给**不同的描边色**（金/青/绿/红），观众才跟得住"哪块飞到哪儿"
- **旋转必须 `setRotAbout(deg, cx, cy)`**，cx/cy 是这块包围盒中心；
  用 `setRot`（绕格原点）会让块整个飘出去
- 描边别用白色 —— 白纸上的白边等于没有

### 4. 重拼：查真实坐标、算刚体变换，别"摆一摆看效果"

这一条我挣扎了四轮，最终结论只有一句：**四块在目标形状里的位置是算出来的，不是摆出来的。**

正确顺序：
1. 找到这套四块在目标形状里的**真实顶点坐标**（查资料，不要自己凑，凑不出来）
2. 用鞋带公式验：四块面积和 = 原图面积，缝面积 = 差的那一格
3. 每块算「绕自己包围盒中心旋转 θ + 平移到目标中心」，**没有 scale**
4. 错开时间依次落位

细节和坐标表见第 8 条。

### 5. "拼"的感觉来自"一块一块落位"，不是来自淡入，更不是来自拉伸

纯淡入 = 一块纸凭空变成另一块纸，没有动作。
四块**同时**飞过去也不行 —— 观众跟不上哪块去了哪，只看到一团东西在动。
`scaleX` 展开更糟，那是把纸拉长（见第 8 条，用户当场否过）。

正确：**错开 0.4~0.5 秒依次落位**，每块落位时描边闪白 + 屏幕轻震，
四个"咔"，观众才数得清"四块都到位了"。

**过程中最好有一帧"一块还在飞、其余已落位"** —— 这一帧是"在拼"的唯一证据。

### 6. 落位要有反馈

每块落位：描边瞬间变白加粗（0.16s）+ 屏幕 2.6px 轻震。
四个"咔"，观众才数得清"四块都到位了"。

### 7. ★ 拼完必须留痕：接缝不能"一闪就没"

NO.22 第二版拼完之后用一次白光把接缝盖过去，直接切到一张完美的 65 格纸。
用户当场否掉：「不要一闪就闪到一张完美的纸，**可以保留拼接造成的拼接线**。」

道理：**拼合的意义就在那道缝上**。缝一擦，观众看到的是"变魔术"，不是"拼"。
剪拼类谜题的答案本身就是"缝攒成一格"，接缝消失等于把答案也擦掉了。

做法：

| 项 | 参数 |
|---|---|
| 接缝位置 | 和四块的目标区间对齐（不要随便放） |
| 接缝形态 | **上下两段、错开 2~3px** —— 一条笔直到底的线看着像格线 |
| 每段再歪 1~2° | 手工拼的东西不会正 |
| 深线 + 浅高光 | `#0A1622` 3.2px + `#FFFFFF` 1.6px 偏移 2px，读成"两片纸叠着" |
| 保留时长 | **一直到片尾**。数格、写名字的时候都在 |

### 8. ★ 多块拼合：只许刚体运动，不许"拼回去再整体拉伸"

NO.22 这条我走了四轮，前三轮全是错的，用户每次都一眼看穿：

| 轮 | 做法 | 为什么假 |
|---|---|---|
| 1 | 给每块指定"目标小矩形"再各自缩放 | 三角形只填满矩形的一半，中间破大洞 |
| 2 | 四块拼回原位 → **整体仿射变换** sx=13/8, sy=5/8 | **纸被拉长了**。用户原话：「这不是现实中说不通吗」 |
| 3 | 加白闪过渡 | 一闪换一张纸，等于变魔术 |
| 4 | **查真实坐标，纯旋转 + 平移** | ✅ 拼得严，缝就是答案 |

**铁律：拼纸不许出现 scale。** 剪拼是刚体运动（平移 + 旋转，最多翻面），
任何 `scale` 都是在作弊，观众看得出来：纸的格子会变成长方形。

#### 落位变换怎么算（三行）

SVG 里 `rotate` 是绕**局部原点**转的，所以要把"绕中心转"补回去：

```js
// c: 这块局部包围盒中心（格坐标）× 格边长；C: 目标位置的中心（画布坐标）
const put = (pc, c, C, deg) => {
  const th = deg * Math.PI / 180, cs = Math.cos(th), sn = Math.sin(th);
  const cx = c.x * DC, cy = c.y * DC;
  pc.setRot(deg);
  pc.move(C.x - (cx * cs - cy * sn), C.y - (cx * sn + cy * cs));
};
```
- `deg` 只能是真实需要的角度（这次是 0 或 90），**`put` 里没有 scale，也不许加**
- 目标中心 = `(BX + 目标包围盒中心.x * DC, BY + 目标包围盒中心.y * DC)`
- 先拿一块手算验证符号（`rot=90` 时 `R(x,y) = (-y, x)`），再批量写

#### 怎么看"拼的过程"对不对

渲染前抽这四帧，逐张问"这一块是从哪来的、要落到哪"：
1. 三条切线都画完了吗（一条线一趟剪，不能"自己断"）
2. 四块分开了吗（各自形状可辨、互不重叠、不出画）
3. **中途有一块还在飞、其余已落位**吗（这一帧最能说明"在一块一块拼"）
4. 全落位后，缝还在吗

第 3 帧是关键。四块同时飞、或者淡入，都不叫拼。

#### 缝要留，而且要留对

- 缝的形状是解出来的（平行四边形），不是"随便画一条线"
- 位置：四块拼完后自然留下的空缺，**不能铺纸底把它填掉**
- 4×5 的格位层只用来数格子/高亮，别铺纸面
- 拼的过程中空隙会一块一块被填上，最后只剩那一条 —— 这个过程本身就是最好的解释


#### 色标要留到片尾（用户点名要的）

切开时给四块不同颜色的边，不是装饰，是**身份标记**：观众靠它跟住"哪块去了哪"。
所以拼完**不能立刻变灰变淡**。用户原话：「这个在拼接之后也可以保留着我觉得挺好的」。

保留的三条：

| 项 | 做法 |
|---|---|
| 本体描边 | 保持彩色，宽 3，`stroke-opacity` 恒为 1，**不随落位改变** |
| 荧光感 | 同色外晕：宽 15~17、`opacity` 0.30、`stroke-linejoin: round`，垫在纸面**下面** |
| 活气 | 四条错开相位呼吸（`0.30 + 0.10*sin(tl*1.7 + i*1.3)`），顺便喂 `_alive` |

**配色要让开"缝"**：缝是答案，颜色最重（红）。四块不能用红，否则红边和红缝糊成一片，
观众分不清哪条是纸边、哪条是缝。这次用 金 / 蓝 / 绿 / 青。

拼合严密时相邻两条边会重合、颜色叠加成混色 —— 这是正常的"拼图感"，不用救。

**加分**：台词说到"还是那张纸 / 一块没多"的时候，四块荧光边一起亮一下，
这句话就有了画面证据，不用另加元素。

### 9. 少用"白光遮丑"

白光一闪是"剪辑手法"，不是"动作"。它能救接缝，但救不了"拼"这个动作本身。
真拼不严的时候，正确顺序是：**先想办法让它拼得严**（验面积、算旋转），
实在不行再用"淡入 + 接缝保留"，而不是"闪一下换一张"。
