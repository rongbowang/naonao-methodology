# 画面升级 · 诊断与改造方案

- **账号**：脑脑不老佬
- **日期**：2026-11-01
- **依据**：NO.17 成片逐帧诊断（8 个关键帧实测）+ 技术栈审查 + 对标视频「故事世界 · 盘点人们被困的最糟糕方式」
- **状态**：待评审；评审通过后进入 Phase 1（两镜样板）

---

## 一、一句话结论

**技术栈合格、美术层缺失、流程有断点。不用换技术路线（SVG + puppeteer 渲染管线全部保留），要换的是"画什么"，并且让 06_画面绘制.md 真正变成唯一画面真相、被逐镜执行。**

---

## 二、NO.17 成片实测诊断（证据）

成片参数：1080×1440 / 30fps / 151 秒，8 个关键帧抽帧实录：

| 时间点 | 画面实录 | 问题判定 |
|---|---|---|
| 0.5s（钩子） | 浅白底 + 一行文字"有座岛，岛上住着两百个人……" | 钩子无画面冲击，纯文字开场 |
| 5s | 红蓝圆点环形图 + 文字 | 示意图代替场景，无角色 |
| 10s（规则） | 问号虚线圆 + 圆点环 + 文字 | 同上 |
| 30s | 黑色人形剪影 + 橙色方块 + 灰色地面线 | 全片唯一"人"= 图标剪影，无表情无姿态 |
| 60s | 蓝点环 + 1 个红点标"1" | 剧情点（"当晚他就走到海边跳了下去"）被画成圆点 |
| 90s | 三个灰矩形 + 红圆 | 抽象图表 |
| 120s（解法） | 同心圆靶心 | 推演图 |
| 145s（片尾） | NO.17 定版 + 下期预告 | 正常 |

**共性**：全程浅白底、一个图形 + 两行字、屏幕约 90% 留白 → 成品是"会动的图文卡"，不是"视频"。

## 三、对标结论（故事世界）

| 维度 | 当前（NO.17） | 目标（故事世界） |
|---|---|---|
| 画面主体 | 几何示意图 | 卡通角色 + 场景 |
| 底色 | 全片统一浅白 | 按内容深浅、氛围向（深海/井洞/峡谷） |
| 角色 | 无（仅 1 次剪影） | 拟人卡通，有表情有姿态 |
| 信息密度 | 低（大面积留白） | 高（满屏场景） |
| 音效 | 无（仅旁白 + BGM） | 逐场景音效（水声/心跳/敲击/信号噪点） |
| 转场 | 硬切 | 硬切 + 雪花噪点（剧情点模拟信号/记忆） |

## 四、根因分析

1. **美术资产缺失**：没有角色库、没有场景库，scenes.js 只能画几何图形。
2. **设计语言错误**：画面 = 图形 + 文字，没有回答"谁在哪、干什么"。剧情点（跳海、码头撂话）全部被抽象成圆点/矩形。
3. **流程断点（最严重）**：06_画面绘制.md 已按规范产出、也有签收关卡，但**做视频时没有被执行**——scenes.js 的实现没有与画面文档对账，成品停留在旧示意图水平。文档写了等于没写。
4. **声音单薄**：只有旁白 + BGM 两轨，无音效轨。"表现力"的一半来自音效。

## 五、改造方案

### A. 美术资产库（Phase 1 建骨架，Phase 2 建全）
- **角色**：2.5~3 头身卡通人模板（圆头大眼、实心小手小脚），4~6 个通用角色（叙述者/岛民/守卫/老板/路人），表情变体（平静/害怕/震惊/得意/恍然大悟），姿态变体（站/蹲/走/摊手/发抖）。
- **场景元素**：海岛夜色、码头、海面、圆桌、旅馆走廊、方桌、地面线、窗户光、篝火。每期按内容扩展。
- **氛围层**：背景渐变 + 暗角（radial 渐变）+ 噪点叠加（feTurbulence），可复用组件。
- **规范**：纯色平涂 + 细描边；画面内禁止出现文字（一律后期叠字卡）。

### B. 画面设计语言（每镜重写"画面"列）
- 每镜必须回答：**谁在哪、干什么、什么道具**。
- 剧情点（钩子/绝望/转折/收尾）必须用场景 + 角色；推演点（规则/解法数字演示）可保留示意图，但必须精致（渐层/阴影/动效），不得白底干图。

### C. 钩子镜规范
- 3 秒内必须有画面钩子（场景 + 悬念），禁止"白底 + 大字"开场。
- 示范（NO.17）：夜色海岛俯瞰，两百个卡通岛民围篝火，红眼睛亮红光、蓝眼睛亮蓝光，配海风声 + 篝火噼啪声。

### D. 音效轨（技术栈唯一硬改动）
- timeline.json 每句加 `sfx` 字段（句首触发，可带淡入）。
- mux.py 加第三轨：音效垫在旁白下方 -12~-16dB，不抢话。
- 台词提到"剪/敲门/落水/跳海/坐下"等动作时，音效与动作同步。

### E. 底色政策
- 每期二选一（深/浅）或按镜分组（剧情镜深、推演镜浅），**期内统一**；文字色值随底色切换保证对比度（深底浅字、浅底深字）。

### F. 转场
- 默认硬切（两段分别生成后期剪）；剧情点可用雪花噪点 0.3s（模拟信号/记忆）或黑场 0.2s。

## 六、流程修复（06_画面绘制.md 必须被使用）

现状断点：文档产出 → 签收关卡存在 → **但 scenes.js 实现未与文档对账** → 成品仍是旧示意图。

强制规则（写进交接文档与体检流程）：
1. **scenes.js 每镜必须能逐栏对应回 06_画面绘制.md 的「画面 / 元素 / 动效」三栏**；对不上 = 该镜未完成，不得进入配音。
2. **签收关卡真实执行**：画面文档未签收，不得配音、不得渲染。
3. 体检工具链增加"画面文档比对"项：锚点匹配（_wcheck）+ 元素逐项核对。
4. 资产库建成后，06_画面绘制.md 的「元素」栏改为引用资产库 ID（如 `char/岛民_害怕`、`scene/海岛夜`），保证文档与实现同源。

## 八、验收标准（每期过一遍）

1. 钩子镜 3 秒内有场景/角色，无"白底大字"开场。
2. 全片无"白底 + 大字"镜头（推演镜除外）。
3. 有角色，且表情/姿态对应台词情绪（至少钩子镜、绝望镜、解法镜）。
4. 音效轨 ≥3 类，动作与音效同步。
5. **06_画面绘制.md ↔ scenes.js 逐镜对账通过**（画面/元素/动效三栏一致）。
6. prompt 无文字；底色期内统一；锚点 100% 匹配（_wcheck 通过）。
