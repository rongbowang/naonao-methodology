> 用户决定：**沿用之前的封面风格**（深蓝底 + 金色字），
> 配色、底色、字体颜色一个都不改，只在这个配色方案上做版式优化。

## 二、四个版式（四种说法，不只是换排版）

| 版 | 名字 | 信息架构 | 文案字段 |
|---|---|---|---|
| **A** | 交叠 | 徽章 → **金色大字压在图形上** → 副标题 → 红绿胶囊。图形 45% 不透明度、青色，真的看得见 | `title` `sub` `chips` `num` |
| **B** | 极简 | **只剩一句判断句**，副标和胶囊全删；图形在上，标题压在它下缘 | 只有 `title`（**每行 ≤5 字**） |
| **E** | 对撞 | **上句 / 下句打架**，标题和胶囊全删；图形在左或上 | `e1` `e2`（各 5~8 字） |
| **F** | 数字 | **一个巨大的数 + 一句注解**；副标、胶囊全删，徽章让到左上角 | `num` + `title`（注解） |

每期 4 版 × 3 比例（竖 1080×1440 / 横 1440×1080 / 16:9 1920×1080）= **12 张**。

### 两条硬规则（2026-10-24 用户定）

**① 绝对不做纯文字封面。**
判断标准：图形 `opacity < 0.25` 或者根本没画 → 就是纯文字，直接算错。
A 版原来是 `opacity .075` 的超大水印，等于纯文字，已改成 `.45` 的青色可见图形。

**② 允许图形和文字重叠，但必须换色。**
用户原话：「重叠是允许的，我发现重叠并不会影响效果。但如果是重叠的话……最好换颜色，
不要用相同的颜色来叠加，这样的话看起来不好。」
- 重叠本身**不算错**，`_uchek.mjs` 只输出 `· 重叠 … 色差 N ✅`
- **同色叠加**（RGB 距离 < 70）报 `⚠同色叠加`
- 所以：**图形和文字不能用同一个色**。现状分工 ——

| 元素 | 色 |
|---|---|
| 图形 | **青 `#46D6D2`**（A / E / F）／**灰蓝 `#8AA0BE`**（B，因为 B 没有副标） |
| 主标题 / 巨字 | 金 `#FFD166` |
| 副标题 | 中蓝 `#A8BBD6` |
| 胶囊 | 红 `#FF6B6B` / 绿 `#2FD573` / 青 `#46D6D2` |

> 2026-10-24 踩过的具体事故：图形原来是金的（跟标题同色），A 版副标是 `#A8BBD6`、
> 图形是 `#8AA0BE`，**色差只有 47**，实测重叠 87% —— 就是用户看到的「同色糊在一起」。

```bash
cd 工程文件

{
 "no":    "NO.11",
 "slug":  "8个正常人住进精神病院",        // 文件名
 "art":   "bed",                        // 图形 key，见 js/cover_arts.js
 // 顶层这四个是 A 版（也是兜底）

 "num":   "0",                         // F 版巨字
 "chips": "-装病进去|+12 家全收|0 个识破", // 红|绿|青
 // 四个版式各自的说法（不写就退回顶层那套）
 "variants": {
   "A": {"title":"没人识破","sub":"罗森汉实验 · 标签效应",
         "chips":"-装病进去|+12 家全收|0 个识破","num":"0"},
   "B": {"title":"装疯的人\n全被收下"},          // 每行 ≤5 字，自己写 \n
   "E": {"e1":"派出去：0 个","e2":"揪出来：41 个"},
   "F": {"num":"0","title":"他一个都没派，医院报出 41 个"}
 }
}

# 2) 渲染 + 两轮体检
python _covers.py v11_rosenhan
```

产物进 `每日成果/<发布日>/封面候选/`：

```
封面A_NO.11_xxx.png        1080×1440
封面A_NO.11_xxx_横版.png    1440×1080
封面A_NO.11_xxx_16x9.png   1920×1080
（B / E / F 同）
```

**`chips` 的写法**（沿用旧封面语法）：用 `|` 分隔；
前缀 `-` 红胶囊、`+` 绿胶囊、不写前缀是青胶囊；
`＋` / `＝` / `→` 会渲染成中间的连接符号。

## 四、判据

**版面体检**（`_webtmpl/_uchek.mjs`，逐版逐尺寸）

| 项 | 判据 | 计入错误 |
|---|---|---|
| 越界 | 文字墨迹离画布边 < 16px | ✅ |
| 文字互压 | 任意两个文字元素重叠 > 6×6px（同一排胶囊豁免） | ✅ |
| **图形 × 文字重叠** | 重叠面积占文字 > 4%（只擦边不算） | ❌ **只提示**，允许 |
| **同色叠加** | 上一条重叠且 RGB 距离 < 70、图形不透明度 ≥ 0.25 | ✅ |
| **纯文字封面** | 图形不透明度 < 0.25，或压根没有图形 | ✅ |
| 字号 | A/B/F ≥ 短边/5.2（1080 → 208px）；**E 版 ≥ 短边/9**（对撞长句达不到 208） | ❌ 只提示 |

图形按「墨迹」量（`#art` 内所有子元素 bbox 的并集），不用 svg 容器框 ——
容器是正方，图形往往占不满，用容器会误报大面积重叠。
`chips` 要**拆成每个胶囊单独测**，整块量的话颜色会取成 `#000000`，同色检查直接失效。

**对比度体检**（`_cvqa.py`，对成品图）

| 项 | 判据 |
|---|---|
| 明暗跨度 | P5~P95 ≥ 110 |
| 空白块 | 3×2 分块占用都 ≥ 0.30 |
| 缩略可读 | 缩到 160px 后 SD 保留 ≥ 65% |

**F 版是例外**：一个巨字 + 大面积深蓝，P5~P95 天然只有 30~50
（金色像素占比不到 5%）。这是设计意图，不是缺陷 —— 它靠「一个字」抓人。

## 五、坑（改封面必读）

1. **`.hero` 只在 D 版定位**，其它版式必须 `display:none`，
   否则它跑到画布左上角 0,0，报一堆越界。
2. **`d()` 不许再 `decodeURIComponent`**：`URLSearchParams` 已解码一次，
   参数带 `%`（如 `num="50%"`）二次解码抛 `URIError`，**整页脚本静默死掉**，
   截图照常出但版式完全不生效。
3. **中文长标题要手动换行**：`title` 里直接写 `\n`（JSON 里是 `\\n`），
   页面检测到 `\n` 就不再自动切，避免断在词中间。
4. **量中文大字必须用 `Range`**：块级容器的 `getBoundingClientRect` 会被撑满，
   4 字 208px 实际只有 832px 宽、容器却是 1080，必误报越界。
5. **`art` key 写错不会报错**，会静默退回树懒 → `body.dataset.artmiss` 留标记，
   `_uchek.mjs` 读到就报 `⚠art key 不存在`。
