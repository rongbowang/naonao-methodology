# 画面生动性 · 诊断与改法 · 2026-10-25

> 起点是用户的一句退稿：「第 15 期 56 秒到 1 分 10 秒，那个画面完全没有什么意义啊，
> 就是几个圈儿放到那儿，啥意思呢？能不能做得生动一点？我感觉现在我们所有的视频
> 都还有不够生动的感觉。」

---

## 一、先把「不生动」量出来

以前的四个体检（`_check` / `_overlap` / `_gcheck` / `_dupcheck`）全都只看**这一帧对不对**：
元素有没有出画、文字有没有压字幕、画面文字有没有复读字幕。
**没有一个看「这十几秒有没有在动」。** 所以 NO.15 那 12.8 秒的静止画面，四次体检全绿。

新工具 **`_alive.py`**：

```bash
python 工程文件/_alive.py "每日成果/2026-10-29/NO.15_xxx.mp4"
python 工程文件/_alive.py --all        # 批量跑所有期，做横向对比
```

做法：裁掉顶部品牌栏和底部字幕区（字幕一直在变，会掩盖画面的死），
按每秒 6 帧抽成 108×144 灰度，算相邻帧的平均绝对差。
**连续多少秒 diff 低于阈值 = 这段时间屏幕是死的。**

判据（按 explainroo 的「Something changes every 2 to 4 seconds」折算）：

| 最长静止 | 判定 |
|---|---|
| ≥ 4.0 秒 | **FAIL** —— 观众会觉得卡住了 |
| 2.0~4.0 秒 | WARN |
| < 2.0 秒 | OK |

### 2026-10-25 全量体检结果（NO.10~NO.17）

| 期 | 时长 | 平均 diff | 最长静止 | 静止占比 | 最死的三段 |
|---|---|---|---|---|---|
| NO.17 为了一次拉屎 | 103.7s | 0.70 | **15.5s** | 85% | 51.8~67.3 / 39.8~51.3 / 94.0~103.5 |
| NO.11 8个正常人 | 104.2s | 0.86 | **14.5s** | 75% | 74.3~88.8 / 93.3~104.0 / 61.7~69.5 |
| NO.15 测试都说准（改前） | 114.3s | 0.71 | **14.0s** | 77% | 85.7~99.7 / **58.2~71.0** / 44.7~55.0 |
| NO.13 人越多越没人 | 107.9s | 0.68 | **13.2s** | 79% | 29.5~42.7 / 58.5~68.2 / 80.7~90.0 |
| NO.14 数据也能造假 | 113.2s | 0.50 | **12.0s** | 82% | 87.3~99.3 / 62.8~73.8 / 48.0~57.8 |
| NO.12 手泡水皱 | 74.0s | 1.01 | **11.8s** | 77% | 16.8~28.7 / 62.5~73.8 |
| NO.16 一天两年 | 105.3s | 1.16 | 7.7s | 68% | 55.3~63.0 |
| NO.10 水会逆流 | 69.5s | 0.99 | 5.7s | 68% | 59.2~64.8 |

**8/8 全部 FAIL。平均最长静止 11.8 秒，平均静止占比 76%。**

也就是说：**观众有四分之三的时间，看着一张不动的图在念台词。**
这不是某一期的问题，是整条产线的问题。

有意思的是：NO.16（天体运动，画面本来就在转）和 NO.10（有水在流）是仅有的两期
平均 diff 上 1.0 的 —— 说明**「画面里有个东西一直在动」比「镜头在缓慢推拉」有效得多**。

`新工作流_v2_偷师版.md` 记了从 hypit / vibe-knowledge-film / explainroo 借来的 8 条。

| 4 | **vibe · 先例子后道理** | ✅ 文案层 | — |
| 5 | **vibe · 结尾回场** | ✅ 在用 | 08 镜拉回 00 那张纸 |
| 6 | **lemo · BGM ducking** | ❌ 已废弃 | `USE_DUCK=0`（压缩器泵浦，2026-10-23 撤） |
| 7 | **explainroo · 响度统一** | ✅ 在用 | I=-18.5 / TP=-1.4 |
| 8 | **vibe · 动词真的发生** | ❌ **名存实亡** | 台词说「他照样会点头」，画面上没有人也没有点头；说「就堵回来了」，画面上没有任何东西被堵 |

**规律很清楚：有工具保护的那几条活得很好，靠自觉的那一条死了。**

- 词级锚点有 `_wcheck.py` 校验，匹配不到就报红 → 30 个锚点一个没坏
- 颜色有肉眼一眼能看出破例
- 动词真发生**没有任何检查**，写 scenes.js 的时候最容易被跳过，因为它要多画一轮、多想一步

而「动词真的发生」恰好是这 8 条里**唯一直接管画面生动性的**。
它一退化，剩下的全变成「静态构图 + 缓慢拉远」。

### NO.15 那 17 秒具体错在哪

```js
// 改前的 why 场景（55.31 ~ 72.18，17 秒，占全片 15%）
// 画了：5 个同心椭圆 + 1 个金色虚线框左右晃 + 2 个 chip
```

| 台词 | 画面给了什么 | 观众该看到的 |
|---|---|---|
| 把这几句念给一个完全不搭的人，**他照样会点头** | 5 个青色的同心圈 | 有个人，他点头 |
| 不是你有别人没有的东西，是**人人都有**的一面 | 同一个框在晃 | 不止一个人，人人头上都有 |
| 你说不像，对方一句「你还没看清自己」就**堵回来**了 | 还是那个框 | 一句话把质疑拍回去 |
| 所以它**怎么都对** | 框停了 | 两个相反的答案都成立 |

四个动作，一个都没画。画的三个东西（同心圆、虚线框、两个胶囊）
**全部是抽象符号，读不出任何动词。**

## 三、改法：人 + 动词 + 咬台词点

改完的 05/05b 两镜，逐句对：

| 台词 | 画面上真发生的事 |
|---|---|
| 把这几句念给一个**完全不搭**的人 | 左边金色一个人，右边青色一个人 + 毛线帽 + 眼镜 —— 一眼不是一类人 |
| 这几句（一张纸） | 纸摊在中间，说到「完全不搭」时**一撕两半**，各落到两人头顶 |
| 他照样会**点头** | 右边那个人**头真的上下点两下**（绕脖子转，不是绕头心） |
| 不是你有别人没有的东西 | 两人之间**浮出三个模糊的人影** |
| 是**人人都有**的一面 | 三个人影再亮一档，**左边那个人也跟着点头** |
| 你说**不像** | 左边冒出对话气泡「不像」 |
| 对方**一句** | 右边那个人把手往前一送 |
| 就**堵回来**了 | 一块「驳回」的砖**举起来 → 悬停憋住 → 拍下去**，气泡被打歪 |
| 所以它**怎么都对** | 一张卡上两行相反的答案：**「你外向吗」五星、「你内向吗」也五星** |

### 三条具体手法

**1. 有人。** 台词里出现「谁」的时候，画面上必须真有一个「谁」。
人形画法（`person()`，已写进 NO.15 的 scenes.js，待下沉进 lib.js）：

- 头是一个圆，躯干是**圆角肩 + 底边封口**的闭合轮廓（不是两根竖线，也不是半圆 ——
  半圆会扣在头上像套了个袋子）
- 手臂从肩到髋，**手画成小圆**（对手要能看出"谁举着牌子"，没手就是一根线）
- **加一条地平线**。人不站在地上，就是浮在画面上的贴纸
- 半径默认 **0.09 倍画布高**（1080×1440 → r≈96）。第一版用了 54，
  人物只有 240px 高、在 1440 的画布上占 17%，四周全是空的

**2. 动作用「三段式」咬台词点。**
最典型的对比是那块砖：

```js
// ❌ 第一版：一路平移 0.38 秒飞过去
//    "对方一句"刚出口砖就砸到了，等念到"堵回来了"这五个字时画面早就静了 1.7 秒
const fly = K.seg(tl, tSay + 0.16, tSay + 0.54);

// ✅ 改后：举起来 → 悬停憋住 → 在「堵回来」那一刻拍下去
const tRise = tSay + 0.06, tRiseEnd = tSay + 0.62;   // 举起来
const tDrop = tHit - 0.34, tDropEnd = tHit - 0.06;   // 拍下去
// 中间那段悬停要带轻微浮动，不能定死（定死就是一张静态图）
```

**打击点必须和台词点咬在一起。** 早了 1.7 秒，画面和声音就是两张皮。

**3. 抽象形状要换成有"载体"的东西。**
「5 个同心椭圆」想表达"模糊的自我"，但观众读出来是水波纹、是靶心、是光圈。
规则：**画一个抽象概念，必须给它一个载体（人/纸/砖/手）和一句能读出来的动作。**

这跟 NO.12 画指纹那次是同一个道理：闭合等距的圆一定被读成涟漪，
有断口、有分叉、有皮肤当背景，才是指纹。

## 五、从 explainroo 拿到的 5 条（之前判错了）

`新工作流_v2_偷师版.md` 里对 explainroo 的判断是「画面太素，只借 camera + loudnorm」。
2026-10-25 重新读了它的 `AGENTS.md`（71KB，写得极其具体），**这个判断是错的**。
它真正值钱的是这五条：

| # | 它的做法 | 我们现在 | 该怎么借 |
|---|---|---|---|
| 1 | **Something changes every 2 to 4 seconds**，`check` 会指出「长时间没有新东西出现」 | 没有任何检查 | ✅ 已落地成 `_alive.py` |
| 2 | **camera 跟着旁白走**：场景开始小时镜头贴近，新东西需要地方就放宽；讲到某个东西就推近；结尾拉远给全貌 | 手写关键帧，10 镜里 5 个是缓慢拉远 | 值得做。做法：`_cam` 按元素出现时刻自动生成关键帧 |
| 3 | **motion blur**：最终渲染给有运动的帧加运动模糊，像胶片 | 30fps 无模糊，动起来是"跳格" | 值得试。ffmpeg `tmix` 或 `minterpolate` 后处理 |
| 4 | **`float`**：元素可以带一点点缓慢漂移，"让静止的东西活着" | 没有 | 便宜且立刻见效，进 `lib.js` |
| 5 | **`enter: draw / write`**：手绘风格下形状一笔一笔画出来、文字一个个写出来 | 有 `K.drawTo` 但全片没用过 | 值得试，尤其适合"报告被摊开""字被写上去"这类动作 |

它另外两条工程纪律也值得抄：
- **`check` 会报「文字太小」**（按 854px 宽的预览尺寸算）—— 我们完全没有这个检查
- **整片 contact sheet**（一张图放全片缩略帧），一眼看出哪几镜是空的 —— 比逐帧抽省太多时间

## 9.1 量化对比：差距是可以量出来的

用 `_alive.py` 跑同一套指标：

| 指标 | 墨有意思 | 我们（NO.15 改后） | 倍数 |
|---|---|---|---|
| 平均帧差 | **3.02** | 1.23 | **2.5×** |
| p90 帧差 | **5.55** | 3.80 | 1.5× |
| 静止占比 | **38%** | 66% | 1.7× |
| 最长静止 | **3.5 秒** | 14.0 秒 | **4×** |

它的最长静止 **3.5 秒**，正好落在 explainroo 那条「每 2~4 秒必须有新东西」的线上。

再拆切镜：131.9 秒里真正的硬切只有 **6 次**（13.3 / 17.1 / 78.8 / 89.4 / 93.6 / 127.7），
其中 **17.2~78.8 连续 61.5 秒没切过镜**。
→ **它不是靠切镜制造节奏，是靠镜内的元素变化。** 这一点和我们「一镜到底」的选择是一致的，
所以我们缺的不是切镜，是**镜内的动作密度**。

## 9.2 它的八条手法

### ① 一个角色，一条姿态线
圆头 + **一个点眼** + **一条嘴线**（嘴的方向管情绪：平的=平静，下弯=累/不开心）。
身体不是「圆角矩形躯干 + 四肢」，是**一根连续粗线勾出的姿态轮廓**：
弓背坐姿 → 一笔从脖子到背到腰到腿到脚。换场景只换姿态线，角色不换。

> 这一幕里他从「坐在电脑前弓着背」变成「瘫在沙发上举着手机」，头还是同一个圆，嘴变成下弯弧。

### ② 一块分好格的道具，从头用到尾
「工作记忆只有 4 格」→ **一块看得见的黑板，4 个槽位**。
之后所有戏都在这块板上演：填入 → 圈住 +1 → 顶掉一格 → 擦空 → 重写。
**道具的状态迁移 = 叙事的推进。** 这是全片最值钱的一招。

### ③ 一个量化道具贯穿全片
电量图标：100% → 62% → 50% → 9%。每次出现都在说「还在往下掉」。

### ④ 仿真 UI 当戏道具
「会议邀请 15:00 接受/拒绝」、「@你」（带三个点的输入中）、「改方案」文档卡。
不放抽象的「干扰」图标，而是**观众每天真看到的东西**。

### ⑤ 一处光源
显示器光、台灯、夕阳、发光的鱼漂、「存档点」的菱形光。
暗底 + 单光源 = 电影感。

### ⑥ 背景不是纯黑，是带极淡纹理的深棕
有噪点、有渐变、有远处的光晕。

### ⑦ 学术出处打在画面底部
「Cowan, 2001」「Leroy, 2009」—— 可信度 + 节奏留白。

### ⑧ 章节卡：全黑 + 居中大标题 + 光晕
「兰道尔原理」黑屏 2 秒，节奏的呼吸点。

## 9.3 能借什么、不能借什么

**它没有旁白**，所以画面文字承载了约 60% 的信息量：主标题 3 行（46~52px）铺满上半屏，
副标 2 行补机制，底部还有出处。

**我们有旁白 + 字幕**，画面文字必须让位 —— 这是**结构性的不能照抄**。
照抄的后果是：上屏文字和字幕互相复读，观众不知道该看哪一层。

| 借 | 不借 |
|---|---|
| ✅ 一个角色一条姿态线（换姿势不换人） | ❌ 大标题铺满上半屏（会和字幕抢注意力） |
| ✅ 一块分格道具 + 状态迁移 | ❌ 暖棕木框的皮肤（我们是深蓝 + 金/青/红，别破坏一把尺子） |
| ✅ 量化道具（电量/计数器） | ❌ 逐句念出的整句字幕式文案 |
| ✅ 仿真 UI 当戏道具 | ❌ 纯物镜无人（我们的观众需要「人」来代入） |
| ✅ 单光源 + 暗纹理 | ❌ 章节卡（我们时长紧，没这个预算） |

## 9.4 落到 NO.15：04 镜改造实录

`04_lines`（40.68~54.96，14.3 秒）原来是「一张纸 + 四行文字 + 两个 chip」，
14 秒里只有 4 次淡入，是全片第三长的死段（44.5~55.0，10.5 秒）。

**改成「四格板 + 一支笔逐格写 + 右下角计数器」**：

| 台词 | 画面 |
|---|---|
| 那份报告上写着这么几句话 | 板升起来 → 编号 1~4 逐个弹出 → 四格依次亮起 |
| 你有时候很外向，有时候又想一个人待着 | 笔写进第 1 格「外向 ↔ 独处」→ 编号变绿勾 |
| 你身上藏着不少潜力，只是到现在都还没机会发挥 | 第 2 格「潜力 · 待用」 |
| 你希望别人喜欢你 | 第 3 格「想被喜欢」 |
| 所以对自己要求很严 | 第 4 格「对自己狠」→ 计数器走到 **4 / 4** |

**四个坑（都是改出来的）**：

1. **格子之间的缝要窄。** 第一版格子高 92、缝 68，看起来是 4 个独立胶囊，
   不像「一块板上的 4 格」。改成高 141、缝 8，才读成一块板被分成了 4 行。
2. **不能只用词锚点起笔。** 用 `W(shot,i,"外向")` 会让笔晚 1~2 秒才动，前面干等。
   格 1~3 改用**句级锚点** `LB(shot,i)[0]`，句子一出口笔就开始写。
3. **写字的时长要跟句子走**：`writeDur = min(句长 × 0.82, 2.6)`。
   写太快（1.15 秒）句子里剩下 2 秒是空的；写太慢像慢动作。
4. **一格写完后画面还得再动一下** —— 编号数字变成**绿勾**。否则「写完」这个动作没有落点。

**效果**：44.5~55.0 那 10.5 秒死段 → 缩到 45.3~51.0 的 5.7 秒。
全片平均帧差 1.16 → **1.23**，p90 3.36 → **3.80**，静止占比 68% → **66%**。

## 9.5 顺手改的工具：`_overlap.mjs` 加豁免

05b 镜里「驳回」的砖必须压在「不像」的气泡上，才读得出「堵回去」，
但 `_overlap.mjs` 每跑一次报一次 —— **体检一旦长期带噪音，真问题就会被淹掉**。

加了 `data-ok-overlap` 属性豁免：

```js
brick.setAttribute("data-ok-overlap", "1");   // 只豁免互压，不豁免压字幕
```

「压字幕」永远不豁免，那是硬错误。

## 10.2 三个体检工具都改了一轮

都是同一个原则：**体检一旦长期带噪音，真问题就会被淹掉。**

| 工具 | 改动 | 起因 |
|---|---|---|
| `_overlap.mjs` | 加 `data-ok-overlap` 豁免（元素或任一祖先带这个属性 → 不参与「互压」） | NO.15 的砖必须压在气泡上才读得出「堵回去」，但每跑必报一次。**只豁免互压，「压字幕」永不豁免** |
| `_gcheck.mjs` | 加**出血豁免**：宽 ≥1020 或高 ≥1380 的元素不算越界 | NO.12 的水面波纹横贯整屏，一处报 72 次 |
| `_gcheck.mjs` | **压字幕阈值 1104 → 1140** | 1104 是「画面文字」的安全线（`K.SAFE_BOT`），不是「图形」的。树干伸进字幕区边缘是正常的 —— 用 1104 判，NO.17 一棵树报 24 次 |

## 10.3 `lib.js` 加了两个全局手段

### ① 环境呼吸（`stage2` 自动挂）
一层 cx540 cy690 r560 的柔光，`cam()` 每帧驱动它在 0.10~0.15 之间起伏。
**所有场景零改动吃到。** 但实测贡献有限 —— 0.05 的透明度变化在 108×144 缩略图上 diff 很小。

### ② 大面积扫光（`stage2` 自动挂）
一道 760px 宽、贯穿整屏的柔光，7.4 秒从左边扫到右边，峰值 opacity 只有 0.055。
**这是这一轮唯一量得出效果的全局手段** —— 因为它每帧有 40% 的画面在变。

> ⚠ 一开始做的是 460px 宽 / opacity 0.12，在深蓝底上会**露成一条竖格子**，像屏幕漏光。
> 必须"更宽更淡"（760 / 0.055）才读成掠光。

## 10.4 ★ 最重要的发现：小动作没有用

改完 NO.12 五个镜头，mean 只从 **1.01 → 1.20**。

原因很清楚：`_alive.py` 量的是 **108×144 缩略图的平均差**。
- 水面波纹（5px 线）→ 量不出
- 水下气泡（5~11px 圆点）→ 量不出
- 血管变细（7px → 3px）→ 量不出
- 指纹 1.02 倍呼吸 → 量不出
- 扫描线来回 → 量不出

真正能量出来的只有两样：**大面积明暗变化**、**大物件位移**。

对照能到 3.02 的墨有意思：**它的每一帧至少有 30~40% 面积是"有东西的"**
（弹窗、黑板、桌子、人、光），我们只有 15% —— 深底 + 细线，八成面积是空的。

**所以下一轮的方向不是「再加动作」，是「把画面填满」：**
大面积色块、整块道具进出、章节卡式明暗切换。
