# 镜头配方卡 · 2026-10-23

> 回答那个问题：**它是生成视频「前」的东西。**
>
> 写 `scenes.js` 之前，先挑卡；写的时候把卡里的数字粘进去。不是生成完了再套滤镜。

---

## 一、先说清它治什么病

我把 NO.10~NO.16 七期的 camera 参数全捞出来做了个统计：

| 参数（整行一模一样） | 出现次数 |
|---|---|
| `1.16 → 1.04` 缓慢拉远 | **6 次** |
| `1.14 → 1.06` 轻微拉远 | **15 次** |
| `1.12 → 1.06` 轻微拉远 | **6 次** |

也就是说：**七期一共 60 多个镜头，真正的运镜只有 2 种 —— 「缓慢拉远」和「轻微拉远」。**

看起来每个场景都开了 camera，实际上全片是同一种动作。观众看到第三期就会觉得「这个号的画面都是一个味儿」，但说不出哪里一样。

**病灶不是「没用 camera」，是「每次都从零凭感觉写 s 和 y 的数字，而人的直觉只会在同一个窄区间里打转」。**

配方卡就是把这个区间**撑开**：先把「镜头能怎么动」穷举成 14 张卡，每张有名字、有参数、有适用场景。写新一期时先想「这一镜该用哪张卡」，而不是「这次 s 写 1.12 还是 1.14」。

---

## 二、卡的格式

每张卡 = **名字 + 一句话用途 + 参数 + 可直接粘的代码 + 别用在哪**

`cam()` 只认三样：`s`（缩放，必须 >1）、`x` / `y`（平移，建议 ≤80px）、`t`（镜头内秒）。
一张卡展开成 2~3 个关键帧，中间自动 `easeInOutCubic` 插值。

## 三、14 张卡

### A 组 · 建立空间感（最常用，但别全用它）

#### 1. `PUSH_IN` 推近强调
**用途**：说到关键结论，把镜头往主体压一点，注意力收窄。
**参数**：s `1.06 → 1.15`，y `0 → -14`，4~5 秒。
```js
_cam: [{ t: 0, s: 1.06, x: 0, y: 0 }, { t: 4.5, s: 1.15, x: 0, y: -14 }]
```
**别用**：连续两个镜头都用，会变成「AI 只会推镜头」。

#### 2. `PULL_OUT` 拉远交代
**用途**：把细节放回全貌，或者收尾。
**参数**：s `1.16 → 1.04`，y `-20 → 0`，5~6 秒。
```js
_cam: [{ t: 0, s: 1.16, x: 0, y: -20 }, { t: 6.0, s: 1.04, x: 0, y: 0 }]
```
**别用**：**片尾之外**。这招现在被用滥了（6 次），只用在该收的地方。

#### 3. `PUSH_PULL` 先推后拉
**用途**：先贴近看细节，再退回来给结论 —— 一镜里完成「看清 → 懂了」。
**参数**：`1.06 → 1.16 → 1.05`。
```js
_cam: [{ t: 0, s: 1.06, x: 0, y: 0 },
       { t: 3.4, s: 1.16, x: 0, y: -18 },
       { t: 6.8, s: 1.05, x: 0, y: 0 }]
```
**别用**：镜头本身短于 5 秒，来不及走完三步。

---

### B 组 · 在两个主体之间移动（我们几乎没用过）

#### 4. `PAN_LR` 从左边摇到右边
**用途**：旁白从 A 说到 B，镜头跟着移。**这是最该多用的一张。**
**参数**：s 固定 `1.10`，x `+70 → -70`。
```js
_cam: [{ t: 0, s: 1.10, x: 70, y: 0 }, { t: 3.5, s: 1.10, x: -70, y: 0 }]
```
**别用**：两个主体靠得很近（< 400px），摇起来像抖。

#### 5. `PAN_RL` 从右边摇到左边
同上，x 反过来。用在「先看结果，再回头看原因」的结构。

#### 6. `PAN_SWING` 往返摇（A → B → A）
**用途**：讲「两个东西互相作用」，来回一次就能表现「一来一回」。
**参数**：x `+70 → -70 → +40`。
```js
_cam: [{ t: 0, s: 1.10, x: 70, y: 0 },
       { t: 2.2, s: 1.10, x: -70, y: 0 },
       { t: 4.6, s: 1.10, x: 40, y: 0 }]
```
**别用**：旁白是单向陈述（没有来回关系）时，会显得多余。

---

### C 组 · 上下（差别最大，但用的最少）

#### 7. `TILT_UP` 抬头
**用途**：从地面仰到天上 —— 讲天体、讲高度、讲「往上看」。
**参数**：y `+40 → -50`，s `1.12`。
```js
_cam: [{ t: 0, s: 1.12, x: 0, y: 40 }, { t: 4.0, s: 1.12, x: 0, y: -50 }]
```
**别用**：画面主体在中间，抬起来会把它顶出画（记得核对 y 上限）。

#### 8. `TILT_DOWN` 俯视下沉
**用途**：从全景俯到局部 —— 讲「往下看」「底下还有什么」。
**参数**：y `-40 → +50`。
```js
_cam: [{ t: 0, s: 1.12, x: 0, y: -40 }, { t: 4.0, s: 1.12, x: 0, y: 50 }]
```

---

### D 组 · 强调瞬间（一次一期，用一次就够）

#### 9. `PUNCH` 冲击变焦
**用途**：数字砸出来、结论落地的**那 0.2 秒**，瞬间推一下再松回来。
**参数**：`1.0 → 1.20`（0.12s）→ `1.06`（0.35s）。
```js
// 记得和音效对齐：sfx(box, tImpact, "impact-soft", 0.6)
_cam: [{ t: tImpact - 0.12, s: 1.0, x: 0, y: 0 },
       { t: tImpact, s: 1.20, x: 0, y: -10 },
       { t: tImpact + 0.35, s: 1.06, x: 0, y: -6 }]
```
**别用**：一期超过一次。第二次就不叫冲击了。

#### 10. `SLAM` 砸定
**用途**：一个东西「砰」地落下来并停在画面中央 —— 印章、判决、结论。
**参数**：`1.0 → 1.14`（0.15s，快），之后**完全不动**（后面不写关键帧，停住）。
```js
_cam: [{ t: tSlam - 0.1, s: 1.0, x: 0, y: 0 }, { t: tSlam + 0.05, s: 1.14, x: 0, y: 0 }]
```
**别用**：配 Soft 类音效（声画不匹配会显得假）。

---

### E 组 · 氛围（让画面「活」起来，成本最低）

#### 11. `BREATH` 呼吸感
**用途**：整镜不做运镜，但画面极慢地起伏，看起来不像静止贴图。
**参数**：s 在 `1.10 ± 0.012` 之间，周期 7 秒。
```js
// update 里每帧重算（不用关键帧）
const br = 1.10 * (1 + 0.012 * Math.sin(tl * 0.9));
ctx._cam = [{ t: 0, s: br, x: 0, y: 0 }];
cam(ctx, tl);
```
**别用**：需要精确对准某个位置时（呼吸会让构图一直微动）。

#### 12. `HANDHELD` 手持微震
**用途**：讲现场、讲事故、讲情绪紧张的段落。
**参数**：x/y 高频抖动 ±3px，s 固定。
```js
const jx = 3 * Math.sin(tl * 7.3) + 1.6 * Math.sin(tl * 13.1);
const jy = 2.4 * Math.cos(tl * 9.4) + 1.2 * Math.cos(tl * 15.7);
ctx._cam = [{ t: 0, s: 1.12, x: jx, y: jy }];
cam(ctx, tl);
```
**别用**：讲精密数据/仪器时（会显得不严谨）。

#### 13. `FOLLOW` 跟拍
**用途**：有个东西在画面里真的在动（球在滚、茶叶在爬），镜头跟着它。
**参数**：x/y 跟着物体的实际坐标走，s 固定。
```js
// 假设 obj 的位置是 (objX, objY)
const fx = K.clamp((540 - objX) * 0.35, -80, 80);
const fy = K.clamp((720 - objY) * 0.30, -80, 80);
ctx._cam = [{ t: 0, s: 1.12, x: fx, y: fy }];
cam(ctx, tl);
```
**别用**：物体只在原地转（没有位移），跟拍会变成无意义抖动。

#### 14. `ORBIT` 环绕（⚠ 需要先扩 `cam()`）
**用途**：讲「从不同角度看同一个东西」。
**现状**：`cam()` 只做 `translate + scale`，**不支持 rotate**。要做这张卡，得给 `cam()` 加第四个参数 `r`（旋转角度，单位 deg），并接受「旋转会露出画面四角」的代价 —— 要么 s 提到 1.25 以上留余量，要么把背景画到 1200×1600。
```js
// 扩展后的写法（现在还不能用）
_cam: [{ t: 0, s: 1.26, r: -3 }, { t: 5, s: 1.26, r: 3 }]
```
**结论**：先不做。等 14 张里有几张被用熟了再回来扩。

## 四、怎么选卡（每镜只选一张）

写每一镜之前问三句：

1. **这一镜有两个主体吗？** → 有：`PAN_LR` / `PAN_RL` / `PAN_SWING`
2. **这一镜在强调某个瞬间吗？** → 是：`PUNCH` / `SLAM`
3. **都没有？** → 那是「陈述镜」，用 `BREATH` 或 `HANDHELD` 让它活着，**不要再写 `1.12 → 1.06`**

**一期 8~9 镜的配比建议**：

| 类型 | 数量 | 卡 |
|---|---|---|
| 陈述镜（垫底） | 3~4 | `BREATH` / `HANDHELD` |
| 主体间移动 | 1~2 | `PAN_LR` / `PAN_SWING` |
| 强调瞬间 | 1 | `PUNCH` 或 `SLAM` |
| 空间感 | 1~2 | `PUSH_IN` / `PUSH_PULL` |
| 收尾 | 1 | `PULL_OUT`（只在最后一镜） |

**一期里每张卡最多用 1 次**（`BREATH` 除外，它是垫底，可以多用）。

## 五、和 video-shotcraft 的 152 张卡是什么关系

video-shotcraft 那 152 张是 **Remotion 的 TSX 组件**（依赖 React），我们这套是 **Canvas/SVG + DOM**，代码不能直接搬。

但**卡的名字和参数区间可以借** —— 它就是一份「运镜词汇表」，而词汇表是跨引擎通用的。我们这 14 张是照着自己的引擎重写的，只保留能用的。

它比我们强的地方有三处，都在它的卡里体现：
1. **2.5D 运镜**（真实页面截图当素材，做视差和景深）—— 我们是手绘 SVG，用不上，但 `ORBIT` 那张卡是同一路的
2. **节奏卡点**（切点对齐 BGM 的拍子）—— 我们没做，因为 BGM 是循环垫底不是主导
3. **卡上直接标了音效**（每张卡自带该配的 SFX）—— **这条可以学**：以后每张卡后面加一行「配哪个音效」

---

## 六、怎么维护这份表

- 每做完一期，如果用了新写法，**补一张卡进来**（名字 + 参数 + 代码）
- 如果某张卡连着三期没用过，说明它不好用，删掉
- 卡不追求多，追求「看到这个画面需求，立刻知道用哪张」
