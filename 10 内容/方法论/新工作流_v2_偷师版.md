## 三、新期开工：完整命令序列

```bash
cd 工程文件/_webtmpl
python newep.py vNN_xxx            # 派生（现在自动带 lib.js / 三个体检脚本 / tts_resume / bgm 双拷）

cd ../vNN_xxx
# ① 写 script.py（声明 BAODIAN / BAODIAN_TYPE）→ python ../check_style.py script.py
python ../gen_cues.py              # 生成 cues.json
python tts_resume.py               # 用 venv python！edge-tts 云扬 +8%

cd web
python gen_timeline.py             # timeline.json + timeline.js（逐字时间在这里产生）
python build_voice.py              # 拼整轨 voice.wav
# ② 写 js/scenes.js → 体检三连
node _check.mjs --n 16             # 元素数 / 画面文字 / 越界 / console
node _overlap.mjs                  # 文字互压 / 压字幕
python ../../_dupcheck.py ../       # 画面文字 vs 字幕 复读检查
node capture.mjs --par 6           # 渲染（顺便写 sfx.json）
python mux.py                      # ducking + 音效 + 双遍 loudnorm + limiter
node cover.mjs --no NO.xx --title "…" --sub "…" --slug "…" --chips "…"   # 三版封面
```

⚠ **`capture.mjs` 用的是 8130 起的端口，一期一跑，不能两期并行**。第二个进程会 `EADDRINUSE` 退出，
但后面的 `mux.py` 仍会用**旧帧**合成出一个「看起来成功」的成片——多期必须串行，并行只能用在 TTS 那一步。

## 五、坑清单（全部踩过）

| 坑 | 症状 | 解法 |
|---|---|---|
| camera 平移不配 s>1 | 露出画外空白，体检报越界 | 平移量 ≤ 80px，且 `s ≥ 1.04` |
| camera 放大 1.16 倍 | 顶部元素被顶进品牌栏 | 画面文字从 y≥258 往下排，只用到 y≤990 |
| SVG `<g>` 用 popIn | 元素飞出画外 | 一律用 `gpop()` |
| SVG 镜像 | 中点塌成竖线，画面像全空 | 用 `gflip()`，别手写 `scale(s,1)` |
| 纯色大圆做光晕 | 在深底上显成一块脏灰 | 用 `glow()`（径向渐变） |
| 图形压字幕 | `_overlap.mjs` 管不到图形，它只比文字矩形 | 太阳这类「露一角的圆」：`cy + r ≤ 1104`；射线只排左/上/右 |
| 画面文字与字幕复读 | `_dupcheck.py` 相似度 ≥0.55 | 不是换同义词，是**换成字幕没给的新信息** |
| update 锚点与台词行数不齐 | `LB(shot,i)` 越界被夹到最后一行，整段动画压到句末爆发，观感「前言不搭后语」 | 按真实行数绑锚点，2 句就 `l(0),l(1)` |
| 单遍 loudnorm | 目标 -14 只到 -15.9 | 双遍：先 `measure()` 拿 `input_i/tp/lra/thresh`，第二遍带 `measured_*` + `linear=true` |
| 双遍后峰值超调 | AAC 编码真峰值冲到 +0.9 dBFS，会削波 | 串一道 `alimiter=limit=0.794:level=disabled`（`level` 不关会把峰值反拉到 0dB） |
| 改 script.py 后不重跑 gen_cues | TTS 按旧 cues 合成，白跑，timeline 也跟着错 | **改台词必须从 `gen_cues.py` 重走** |

## 十、素材现状（2026-10-23 更新：音效已补齐）

### ⚠ 先记一次翻车：音效加成了「节拍器」

第一版音效（2026-10-22）我在七期里塞了 **81 个音效点**，平均**每 6~7 秒一个**。
用户听完反馈：「一会儿 duang 一声一会儿 duang 一声，感觉有点怪怪的。」

扫下来问题很清楚：

| 指标 | 数值 |
|---|---|
| 总音效点（七期） | 81 |
| **画面里找不到任何声源的** | **79 个（98%）** |
| 用得最多的 | `ding` 34 次、`whoosh` 13 次、`stamp` 11 次 |

**根本错误：把音效当成「这里很重要」的听觉标记，而不是「画面里正在发生的声音」。**

我们的画面是手绘 SVG 线条 —— 没有水、没有纸、没有金属在响。给一张线条画配 `ding`，
观众听到的是一声和画面**毫无关系**的响动。那个「duang」就是 `stamp`（低频盖章）和 `impact`。

### 音效四条铁律（2026-10-23 起）

1. **有声源才配，没有就不配。** 判据是「这一帧画面上有没有东西在发出声音」：
   水在流 / 笔在写 / 章盖在纸上 / 纸被翻动 / 硬币落下 —— 有，配；没有（人在看、数字在变、太阳在转）—— **不配**。
2. **一期 3~5 个，最多 6 个。** 70~90 秒的片，平均 15~25 秒一个。
3. **禁用「无源强调音」**：`impact-*` / `boom-*` / `cinematic-hit-*` / `stamp` / `ding`
   —— 除非画面上真的有碰撞、爆炸、盖章、铃铛。
4. **数字在涨 ≠ 有声音**，但 `data-countup-*` 可以算「半合法」（画面确实在显示数字递增），一期最多 1 处。

|---|---|---|

### 音效库

`工程文件/sfx/` 现在是 **325 个**（原 5 个 + 新拉 320 个）。

新拉的是 **wyzowl/sfx-kit**（GitHub，CC0-1.0，48kHz/24bit WAV，66MB）：
320 个原创音效，28 个分类，而且**专为 AI 工具设计** —— 每个音效都带
`use_for` / `avoid_for` / `duration` / `fits_seconds` / `sync.at` / `lufs` / `under_voiceover_db`。

索引：`工程文件/sfx_catalog.json`；速查：`工程文件/音效库说明.md`。

| 升级 | 做法 | 效果 |
|---|---|---|
| **sync 对齐** | `sfx()` 的 `tl` 改成「动作该发生的那一刻」，`mux.py` 按 `sync_at` 把起点提前 | 音效**峰值**落在动作上，不是「动作开始了才听见声音」 |
| **响度归一** | 所有音效先归到 `-19 LUFS` 再乘 `vol` | 老素材 whoosh(-12.2) 和 ding(-17.6) 差 5.5dB，以前写同样 `vol` 会一炸一闷 |

## 十一、音频响度结构（2026-10-23 第二次翻车后重做）

### ⚠ 翻车现场：用户说「声压强、有侵略感、响度变大了」

这不是错觉，是**三层错误叠在一起**。实测数据：

| 指标 | 旧结构 | 病因 |
|---|---|---|
| `voice.wav` 原始响度 | **-25.6 LUFS** | edge-tts 出来的旁白本来就很小声，没人管它 |
| 旧版成片响度 | **-24.9 LUFS** | 基本等于没处理，全靠平台自己拉起来 |
| BGM 乘 0.22 后 | **-26.5 LUFS** | **只比旁白低 0.9dB**，两轨在打架 |
| 混完一把 loudnorm | 硬拉 **+11dB** | alimiter 全程介入，动态被压平 |

**最硬的一条铁证**：旧结构里「气口（只有 BGM）」是 **-14.1 dB**，
「说话」是 **-15.7 dB** —— **音乐比人声还响 1.6dB**。人声根本压不住音乐，
这就是「侵略感」的来源，跟总响度调多少其实关系不大。

（旧版备份 -24.9 反而不吵，是因为响度太低，BGM 跟着一起小；但它会被平台强拉，
拉的时候用平台的限幅器，动态照样被压平，而且噪声一起上来。）

### 新结构：三层分离

```
① 旁白先单独归一    voice.wav -25.6 → loudnorm 双遍 → 目标 -16（实际约 -19，TP 限制）
② BGM 按相对关系反算  不再写死 volume，而是「固定垫在旁白下方 15dB」
                     → 实测 volume 从 0.22 降到 0.131，BGM 落到 -31 LUFS
③ 整体只做小幅增益    目标 -15.5，实际 -16.4（不再靠一把 loudnorm 拉 10dB）
```

**关键参数（`_webtmpl/mux.py` 顶部）**：

| 常量 | 值 | 含义 |
|---|---|---|
| `VOICE_I` | -16.0 | 旁白预归一目标（口播标准） |
| `VOICE_TP` | -3.5 | 归一后的真峰值，给最后增益留 2dB 余量 |
| `BGM_UNDER` | **15.0** | BGM 固定垫在旁白下方多少 dB ← **最重要的一个** |
| `TARGET_I` | -15.5 | 最终整体（略低于平台常见的 -14，听感更从容） |

### 实测对比（七期平均）

| 指标 | 旧结构 | 新结构 | 变化 |
|---|---|---|---|
| 整体响度 I | -14.8 LUFS | **-16.4 LUFS** | **-1.6dB** |
| 响度范围 LRA | 2.0 LU | **2.7 LU** | **+0.7（动态回来了）** |
| 气口（BGM 独奏） | -14.1 dB | **-26.8 dB** | **-12.7dB** |
| 说话 | -15.7 dB | **-16.1 dB** | 基本不变 |
| **人声压住音乐** | **-1.6dB（音乐更响）** | **+10.6dB（人声压住）** | **质变** |

### BGM 垫低多少才对：做过对照实验

| 垫低 | 气口dB | 说话dB | 人声压住 | 判定 |
|---|---|---|---|---|
| 10dB | -26.3 | -17.9 | 8.5dB | 不够，音乐还想往外冒 |
| **15dB** | **-31.3** | **-18.4** | **12.9dB** | **采用** |
| 18dB | -34.3 | -18.5 | 15.8dB | 音乐几乎没有存在感 |

### 旁白拉响的三种做法也对比过

原始 `voice.wav` 的**峰均比高达 24dB**（正常播报 12~16dB），要拉 9.6dB 必然会碰峰值。

| 做法 | 结果 I | LRA | 结论 |
|---|---|---|---|
| `acompressor` + 增益 + 限幅 | -18.1 | 2.6 | 压缩伤了动态 |
| 纯 `volume` 增益 + 限幅 | -19.2 | 2.7 | 限幅削尖峰 |
| **loudnorm 双遍（采用）** | -17.5 | **2.9** | **三个里保动态最好** |

### 一句话记住

> **响度的绝对值不是问题，「谁压住谁」才是问题。**
> 口播视频里，人声说话时必须比「只有 BGM 的气口」显著更响（≥10dB），
> 否则观众就会觉得「吵」——哪怕总响度只有 -16。

**别再改回去的两个坑**：
1. 不要写死 `BGM_VOL`。BGM 素材每期可能换，写死就等于赌它响度不变。
2. 不要在混完后再一把 loudnorm 拉 10dB。要么旁白先归一，要么别拉。

### ⚠️ 2026-10-23 晚：上面这套被推翻了（第三次返工）

用户听完说：「声音很怪，而且 BGM 的声音太小了。**之前我说声音很怪，感觉不是因为
BGM 声音大的问题**。」——他要纠正我上一的判断。

我把三个嫌疑逐个量化，结论是**我上一版修的完全不在点上**：

| 嫌疑 | 实测 | 判定 |
|---|---|---|
| **sidechaincompress 的泵浦** | BGM 电平抖动标准差从 4.02 → 5.08，**最深被压掉 14.6dB**，气口一停又弹回 | ★**「怪」的头号元凶**。音乐在喘气。 |
| **旁白被压扁** | 峰均比 **13.8 → 9.8dB**（LRA 3.8→2.9） | ★第二元凶。说话起伏被抹平，发扁发硬 |
| 音效归一化放大失真 | 放大后真峰值都在 -10dB 以下 | ✗ 没削波，不是它 |
| BGM 太大 | 上一版垫低 15dB（-31 LUFS） | ✗ 反了，是**太小** |

**两个我犯的错**：

1. **`loudnorm` 会偷偷压缩。** 它虽然写着 `linear=true`，但只要 TP 超限就自动转
   动态模式。`voice.wav` 峰值 -1.6、I 只有 -25.6，一拉 9.6dB 必然超 TP，
   于是它压了 4dB 动态——而我以为在做「纯增益」。
2. **`sidechaincompress` 是压缩器，不是音量开关。** 它的 release=350ms 配上
   0.8 秒的气口，就是「压下去—刚松—又压下去」的循环，听感必然是喘。

**第三次的最终方案（现行）**：

| 项 | 值 | 为什么 |
|---|---|---|
| `USE_DUCK` | **0** | 彻底去掉压缩器。BGM 音量恒定，不喘 |
| 旁白处理 | **纯 `volume` + `alimiter`**，不用 loudnorm | 实测峰均比 11.7 vs loudnorm 的 10.4 |
| `VOICE_I` | **-20.0** | 只拉 5.6dB。之前拉到 -16 是过度 |
| `VOICE_LIMIT` | -3.0 | 只削尖峰，不做压缩 |
| `BGM_UNDER` | **10.0** | 从 15 抬到 10，BGM 从 -31 到 -30，听得见 |
| `TARGET_I` | **-18.5** | 整体从 -16.4 降 2.5dB |
| 最后一步 | 测一次算增益 + 限幅，**不用 loudnorm** | 避免第二次压缩 |

**实测结果（七期）**：

| 指标 | 上一版 | 现在 |
|---|---|---|
| 人声峰均比 | 9.8 dB | **12.0 dB**（原始 13.8） |
| 人声 LRA | 2.9 | **3.0** |
| 成片 I | -16.3 | **-18.9** |
| 气口（只有 BGM） | -31 | **-28**（听得见了） |
| ducking 泵浦 | **最深 14.6dB** | **无** |

**两条新铁律**：
1. **`loudnorm` 不是纯增益工具。** 只要素材峰值高、响度低（edge-tts 就是这样），
   它就会偷偷压动态。要保动态就用 `volume` + `alimiter`，自己算增益。
2. **口播视频不要用 `sidechaincompress` 做 ducking。** 它的泵浦感在
   「一句话一停」的语速下必然被听出来。宁可把 BGM 整体做低，也不要让它跟着人声呼吸。

## 十二、运镜配方（14 张卡）

见 `工程文件/运镜配方.md`。

**为什么做这个**：把 NO.10~NO.16 七期的 camera 参数全捞出来统计，发现
「1.16→1.04 拉远」用了 6 次、「1.14→1.06 拉远」用了 15 次、「1.12→1.06」用了 6 次 ——
**60 多个镜头，真正的运镜只有 2 种**。开是开了 camera，但全片同一个味儿。

病灶不是「没开 camera」，是**每次从零凭感觉写 s 和 y，而人的直觉只在一个窄区间打转**。

14 张卡分五组：建立空间感（3）/ 主体间移动（3）/ 上下（2）/ 强调瞬间（2）/ 氛围（4）。
每张有名字、参数、可粘代码、和「别用在哪」。

用法：**写 scenes.js 之前先挑卡**，一期 8~9 镜按配比选（陈述镜 3~4 / 移动 1~2 / 强调 1 / 空间感 1~2 / 收尾 1）。
一张卡一期只用一次（`BREATH` 除外，它是垫底）。
