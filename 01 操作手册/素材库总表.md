## 一、BGM：166 首（解决「七期同一首」）

### 来源

[**btahir/open-lofi**](https://github.com/btahir/open-lofi) — 166 首 lo-fi，
作者用 Suno v5 生成后**捐入公共领域**，CC0-1.0，48kbps 级 mp3，可商用可改。

### 为什么是它

之前七期用的是**同一首** bgm.wav（md5 完全一致，144.9 秒）——观众听到第七期，
同一个背景音乐播了七遍。这是素材里最该补的洞。

选 lo-fi 不选「史诗配乐」的原因：知识口播的 BGM 要求是**不抢注意力**，
lo-fi 的鼓点轻、无强旋律转折、适合长时间垫底。真正抢戏的那种（有大旋律线的）
反而会让人分心。

### 怎么选

`工程文件/bgm_catalog.json` 每首带 `category / category_cn / duration / lufs / lra / fit`。

**分类与适用场景**（按我们的题材匹配）：

| 分类 | 中文 | 适用 | 首数 |
|---|---|---|---|
| `activities` | 专注 / 日常 | 讲「怎么做」、动手实验、生活科学 | 29 |
| `ambient-lofi` | 氛围 / 梦境 | 宇宙、深海、心理、抽象原理 | 21 |
| `hybrid` | 电影感 / 世界 | 有戏剧性的科学史、翻车、反转 | 8 |
| `asian-lofi` | 东方 / 禅 | 自然、生物、时间、静物 | 8 |
| `jazzhop` | 爵士 / 书房 | 讲书、讲概念、「有人研究过」 | 12 |
| `seasonal-weather` | 季节 / 天气 | 气象、地理、季节 | 27 |
| `chillhop` | 温暖律动 | 轻松日常 | 8 |
| `late-night` | 深夜 / 霓虹 | 深夜实验、孤独感 | 18 |
| `soul-rnb` | 灵魂 / 温暖 | 情感类；**慎用，容易煽** | 21 |
| `funk-soul` | 放克 / 复古 | 节奏强，**容易抢话，一般不用于口播** | 14 |

**`fit` 分** = 时长够（≥100s +2 / ≥140s +1）+ LRA 接近 3（越稳越高）+ 响度接近 -14。
**分高 ≠ 好听**，它只衡量「垫底稳不稳」。好不好听得你听。

### 怎么换（一行搞定）

每期 `web/bgm.json`：

```json
{ "id": "orbiting-in-silence", "title": "Orbiting in Silence", "why": "公转/宇宙" }
```

改 `id` → 重跑 `python mux.py` → 重归档。**不用重渲画面。**

### 防重复

`工程文件/bgm_used.json` 记录哪首被哪期用过。`newep.py` 派生新期时会**自动跳过**
已用的曲目，从 `activities / ambient-lofi / hybrid / jazzhop / asian-lofi / chillhop`
里挑 `fit` 最高的。想指定就 `python newep.py v17_xxx --bgm <曲目id>`。

### 七期现在的分配

**2026-10-23 晚起：七期统一用 `theme-original`（原来那一首，md5 `8bb6ddbe`）。**

用户原话：「BGM 的话，我感觉换成之前那一个就行，不需要经常换 BGM。」
所以之前「七期各配一首」的做法已作废，166 首降级为**备选库**，`newep.py` 派生新期
默认也锁 `theme-original`，要换才用 `--bgm <id>`。

| 项 | 值 |
|---|---|
| 主用曲 | `theme-original`（144.9s，I=-13.3，LRA=2.4） |
| 位置 | `工程文件/bgm/theme-original.wav` |
| 七期 `bgm.json` | 全部指向它 |

### 实测（第三次音频返工后，七期重混未重渲）

| 指标 | 上一版 | 现在 |
|---|---|---|
| 成片 I | -16.3 | **-18.9** |
| 人声峰均比 | 9.8 dB | **12.0 dB** |
| 气口（只有 BGM） | -31 | **-28** |
| ducking | 最深压 14.6dB | **已关闭** |

**曲目响度各不相同（-13.0 ~ -14.2），所以 `mux.py` 按「垫在旁白下方 10dB」反算音量**，
不写死 `volume`。换曲不用改代码。

## 二、手绘 SVG：539 条索引（505 个原文件）

### 来源

[**CocoMaterial**](https://cocomaterial.com) — 3386 个手绘线稿，CC0-1.0。
代码 GPL-3.0 开源，素材本身 CC0，可商用可改无需署名。

### 为什么只拿了 539 个（不是 3386）

库里 **60% 是噪音**：`people` 1031 个、`flag` 161、`letter` 98、`typography` 119、
`longhair` 430 —— 这些是「头像 / 国旗 / 字母」，我们画面里的人是简笔小人，用不上。

按 11 组题材白名单筛完 539 条（有 34 条重名或源文件缺失，实际落盘 505 个）：

| 组 | 数量 | 组 | 数量 |
|---|---|---|---|
| 水（瓶/杯/滴/倒/茶叶） | 70 | 动物（蛙/蝎/松鼠/虫/鸟/鱼） | 70 |
| 工具仪器（天平/尺/放大镜/齿轮） | 60 | 书纸笔（书/纸/笔/笔记本） | 54 |
| 建筑（门/窗/厕所/厨房/楼梯） | 50 | 植物自然（树/叶/火/山） | 45 |
| 钱数据（钱/硬币/图表/电脑） | 44 | 人物姿态（思考/指/摔/坐） | 42 |
| 医疗（医生/药/注射器/病毒） | 42 | 天体（太阳/月亮/星/行星） | 35 |
| 人体（脑/心/眼/手/骨） | 27 | | |

### 两种用法

**① 复制 path（推荐，零运行时开销）**

`graphics_catalog.json` 每条形如：

```json
{ "id": "bird_1", "name": "Bird 1", "group": "动物",
  "viewBox": "0 0 95.3 92.3",
  "body": "<path d=\"m 1845.5,19537.7 c …\" transform=\"translate(…) matrix(…)\"/>" }
```

查到了就把 `body` 直接粘进 `scenes.js`，用 `K.sp` 建 `<svg viewBox>` 包起来。
**注意别动 `transform`**——素材原始坐标是大数值（比如 19537），靠 path 自带的
transform 落回 viewBox，删了就跑出画外。

**② 运行时取（`LIB.gfx`）**

```js
// 先让页面加载素材表：<script src="graphics.js"></script>  → window.GFX
LIB.gfx(svg, GFX["bird_1"], 540, 700, 260, LIB.MUTED, 3);
//          parent  item        x    y    w   颜色        线宽(屏幕像素)
```

`gfx()` 已处理三件事：viewBox 等比缩放、`vector-effect:non-scaling-stroke`（线宽按像素算，
不随 viewBox 缩放，否则小图标会粗成墨团）、颜色统一由参数控制。

**验证记录**：`_webtmpl/_gfxtest.mjs` 取 5 组各 1 个跑过 —— 全部创建成功、
path 都在 viewBox 内、`nonScaling` 生效、**无 pageerror**。

### 什么时候别用

我们的画面是**粗线条简笔画**（线宽 3~6px，圆头）。CocoMaterial 是**细线手绘**
（原稿线宽细、细节多）。**混在同一屏里会显得脏**。用它的时候要么整屏统一换成素材风，
要么只把它当「形状参考」——照它的结构自己用粗线重画一遍。

## 四、字体：4 款（含一个必须处理的法律风险）

### ⚠ 现在用的是微软雅黑，商用有风险

`cover.html` 和 `index.html` 里写的是：

```css
--font:"Microsoft YaHei","Source Han Sans CN","PingFang SC",sans-serif;
```

**微软雅黑由方正设计**。Windows 自带 ≠ 可商用——系统授权覆盖的是「在 Windows 内日常使用」，
**把字烧进封面图和视频画面属于商业发布，需要向版权方另行取得授权**。
方正诉宝洁案（2007）就是这个由头。

我们每期封面都是烧进像素的字，这条风险是实的。

### 已经下好、放在 `工程文件/fonts/`

| 字体 | 文件 | 体积 | 授权 | 用途 |
|---|---|---|---|---|
| **思源黑体 SC** | `SourceHanSansSC-Regular/Bold/Heavy.otf` | 50 MB | SIL OFL 1.1 | 正文/画面文字/数字，7 字重里取了 3 个 |
| **得意黑** | `SmileySans-Oblique.otf` | 2 MB | SIL OFL 1.1 | 标题备选，斜体窄身、有速度感 |

### 怎么启用（还没切，等你点头）

在 `cover.html` / `index.html` 的 `<style>` 顶部加：

```css
@font-face{
  font-family:"SHSansSC";
  src:url("file:///D:/桌面/脑脑不老佬/工程文件/fonts/SourceHanSansSC-Regular.otf") format("opentype");
  font-weight:400;
}
@font-face{
  font-family:"SHSansSC";
  src:url("file:///D:/桌面/脑脑不老佬/工程文件/fonts/SourceHanSansSC-Bold.otf") format("opentype");
  font-weight:700;
}
@font-face{
  font-family:"SHSansSC";
  src:url("file:///D:/桌面/脑脑不老佬/工程文件/fonts/SourceHanSansSC-Heavy.otf") format("opentype");
  font-weight:900;
}
:root{ --font:"SHSansSC","Microsoft YaHei",sans-serif; }
```

用**绝对路径**是因为模板在 `_webtmpl/`、派生工程在 `vXX/web/`，两者到 `fonts/` 的
相对层级不同，写相对路径必有一边找不到。

**为什么不直接切**：换字体会改变所有封面的视觉（雅黑和思源黑体在字宽、字重观感上有差），
七期 21 张封面 + 成片画面文字都得重出。**得你先看样张再决定**。

## 五、这次没拿的（以及为什么）

| 候选 | 为什么不拿 |
|---|---|
| **SoundSafari/CC0-1.0-Music** | 7000 首 / **40GB**，来源杂乱、格式不统一（作者自己说「未做标准化」）。166 首精选够用，40GB 是负担。 |
| **Koboyo Icons**（26 万手绘 SVG） | 数量大到没法用，且是「界面图标」语法（按钮/状态），不是「画一个青蛙」。 |
| **Open Doodles / Open Peeps** | CC0 但只有 50~100 个，且是**扁平人物插画**（有填充色块）。我们画面是纯线条无填充，风格不搭。 |
| **位图插画库（unDraw / Storyset 等）** | 我们的画面是**代码生成的 SVG**，位图贴上去不能做逐元素动效，还要处理缩放糊边。方向就不对。 |
| **Remotion / Manim 的素材** | 是框架不是素材，换栈的成本远大于收益。 |

**判断标准**：素材要么能**直接嵌进 SVG 且可动效**，要么能**当形状参考**。
其它一律不要——素材库越大越容易变成「收藏了但没用过」。

## 六、加新素材的规矩

1. **先问「我们的画面是什么」**。纯代码 SVG → 位图素材全都不合适。
2. **先算体积**。BGM 一首 3MB、SFX 一个 200KB、SVG 一个 12KB。按 200MB 预算加。
3. **必须建索引**（`*_catalog.json`）。没有索引的素材库等于没有。
4. **没听过的音乐不进成片**。我听不了，所以每首新 BGM 都要你耳朵过一遍。
5. **授权必须写清**。CC0 / OFL 可以，CC-BY 要署名，其它一律不要。
