# 新工作流：文案 → 审 → 画面 → 审 → 配音 → 作画（2026-11-03 起）

> 用户 2026-11-03 定的流程。**从 11-04（NO.21）起每一期都走这条线**，不再"文案画面一起交"。
> 关键变化：**文案和画面各有一道人工审核关**，审核没过不许进下一步。

## 六步（每步都有明确的"完成标准"）

| 步 | 谁做 | 产出 | 完成标准 |
|---|---|---|---|
| 1 文案 | 我 | `script.py` + `05_剧本_送审.md` | `check_style.py` 退出码 0；送审稿里有爆点/结构/逐句/与上版差异 |
| 1.5 **去 AI 味** | 我 | 同一份 `script.py`（改表达不改事实） | `_humanize.py` ≤4 分 且 `check_style.py` 通过 |
| 2 **审文案** | **用户** | 批注或口头意见 | 用户明确说"这版可以" |
| 3 画面文档 | 我 | `06_画面绘制.md`（19 项 + 4 个量化栏位） | 每镜有包围盒核算、最小可见尺寸、常驻微动、素材锚点 |
| 4 **审画面** | **用户** | 批注 | 用户明确说过 |
| 5 配音 | 我 | `audio/` + `cues.json` | `tts_whole.py --mode all --engine minimax` 跑通，总时长落在题材档位内 |
| 6 作画 | 我 | `web/js/scenes.js` → `_bbox`/`_alive_pre` → `render_all.py` | 七体检里 `_bbox` 压字幕 0、`_alive_pre` < 4s，成片规格核对通过 |
| 7 交付 | 我 | `30 制作/<期>/30_交付/` + `40 出版物/<发布日>/<期号_标题>/` | 见下面「目录结构」 |

**不许跳步**：文案没过审不写画面；画面没过审不配音（配音一改，时间轴和画面全要重来，这是最贵的返工）。

## 作画阶段发现文案有问题的处理

作画时一定会遇到"这句台词没法画 / 画出来观众看不懂 / 时长撑不住"的情况。**不许现场改完就完事**，必须：

1. 记进 `01 操作手册/文案踩坑记录.md`（一条一行：期号 · 原句 · 问题类型 · 改法 · 下次怎么避免）
2. 如果属于**可复用的规律**（不是这一期特有），同时更新 `01 操作手册/制作口诀.md` 或本文件
3. 下一期写文案前**先读这个文件**

## 去 AI 味这一步（2026-11-03 起，固定流程，不许跳）

**为什么单独一步**：`check_style.py` 查的是"这句话能不能说"（禁词、编排话、人称）；
**腔调**它管不了。AI 味的典型症状是排比太工整、结尾强行升华、每句都在解释、
全篇没有一个看得见的东西、节奏像节拍器 —— 这些是"像不像人说的"。

### 两个体检，都要跑
```bash
PY="C:/Users/13071/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
$PY "02 工具/check_style.py" "30 制作/<期>/script.py"     # 禁词 / 编排话 / 人称
$PY "02 工具/_humanize.py"   "30 制作/<期>/script.py"     # 口播 AI 味 0~10 分（≤4 合格）
```
`_humanize.py` 查六项：对称排比 / 强行升华 / 解释腔 / 具体锚点数量 / 口语毛边数量 / 节奏均质。
用户点名要保留的表达（比如"人生巅峰"），在 `script.py` 里写 `HUMANIZE_OK = ["…"]` 豁免。

通用工具 `buhang-humanizer/scripts/ai-taint-score.js` 也能跑，但它只认"首先/其次/综上所述"，
对中文口播基本打 0 分（NO.21 打 0 分却满屏 AI 味），**所以以 `_humanize.py` 为准**。

### 改写五刀（按 skill 的 ai-tells.md，逐类过）
1. **删套话** —— 首先/其次/值得注意的是/由此可见，直接删
2. **破排比** —— "一X…一Y""不是A，是B"三连砍成一击；只留最有力的那个
3. **斩升华** —— 段尾"让我们…""这不仅是…更是…"删掉，换成一个具体动作或短句留白
4. **加毛边** —— 插入口语词（偏偏、差一点、愣是、呢、吧）和破折号插入语
5. **变节奏** —— 长句拆短、允许一句话成段；连续 6 个以上 5~10 字的小句必须打断

### 通过标准（写进送审稿）
- `_humanize.py` ≤ 4 分
- `check_style.py` 退出码 0
- 送审稿里附上"改前 / 改后"对照表（至少 4 行），让用户自己看改了哪里
